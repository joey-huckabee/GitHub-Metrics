# GitHub-Metrics — Level 3 Requirements

## Purpose

This document establishes the Level 3 (L3) requirements for GitHub-Metrics. L3
requirements are implementation-level derivations of the L2 requirements in
[`L2.md`](L2.md): they name the concrete behaviour a maintainer can change and
break, and they are the level at which tests attach.

## Conventions

Each L3 is a single line, because at implementation level the obligation is
almost always one sentence and a full section per item buries it:

```
**L3-<CAT>-<NNN>** · Parent: L2-<CAT>-<NNN> · Verification: <methods>
<statement>
```

An optional `· Evidence: ...` follows the verification methods, and is required
before a non-Test method counts as satisfied.

Verification methods use the DO-178 letters defined in [`L1.md`](L1.md): T, I,
A, D.

**Status is not recorded here.** It is derived in
[`TRACE-MATRIX.md`](TRACE-MATRIX.md) by `scripts/build-trace-matrix.py` from
the `@pytest.mark.requirement` markers in `tests/`. A test claims an L3 by
naming it:

```python
@pytest.mark.requirement("L3-ING-002")
def test_a_byte_order_mark_does_not_hide_the_header() -> None:
    ...
```

## L3-ING: Repository inventory ingestion

**L3-ING-001** · Parent: L2-ING-001 · Verification: T
`read_repository_csv` shall return a `RepositoryRef` per accepted row exposing
`owner`, `repoid`, `full_name` as `owner/repoid`, `url` as
`https://github.com/owner/repoid`, and `source_line` set to the row's 1-based
physical line.

**L3-ING-002** · Parent: L2-ING-002 · Verification: T
The reader shall decode input as `utf-8-sig`, so that a leading byte-order mark
is consumed rather than becoming part of the first header cell.

**L3-ING-003** · Parent: L2-ING-003 · Verification: T
The reader shall hand newline handling to the `csv` module by opening its text
with `newline=""`, so that CRLF and LF inputs parse identically and a newline
inside a quoted field does not split the row.

**L3-ING-004** · Parent: L2-ING-004 · Verification: T
Header cells shall be compared after stripping whitespace and case-folding, the
`owner` and `repoid` columns shall be located by name rather than by position,
and any other column shall be ignored.

**L3-ING-005** · Parent: L2-ING-005 · Verification: T
A row whose every cell is empty after stripping shall be skipped without being
counted or reported, and the `owner` and `repoid` values of an accepted row
shall be stripped of surrounding whitespace.

**L3-ING-006** · Parent: L2-ING-006 · Verification: T
`RepositoryRef.key` shall case-fold both components, and the reader shall use it
to drop a repeated repository, reporting the line of the first occurrence.

**L3-ING-007** · Parent: L2-ING-007 · Verification: T
A quoted field containing a separator shall be read as one cell, and an
inventory of 5,000 rows shall be read by the ordinary code path.

**L3-SRC-001** · Parent: L2-SRC-001 · Verification: T
`parse_reference` shall reduce a slug and every usual GitHub URL form to the
same `RepositoryRef`, including the `www.`, trailing-slash, `.git`, scheme-less
and `git@` variants, shall drop a trailing path such as `/tree/main`, and shall
preserve the case it was given.

**L3-SRC-002** · Parent: L2-SRC-001 · Verification: T
A refused reference shall carry a reason rather than a boolean: `GM-ING-017`
for a host that is not GitHub, naming `GITHUB_API_URL` as the alternative,
`GM-ING-016` for a value that is not `owner/repoid`, stating what is wrong with
its shape, and the same owner and repository codes ingestion uses for a name
that breaks the grammar. An issue from an argument shall carry no line number.

**L3-SRC-003** · Parent: L2-SRC-002 · Verification: T
`is_csv_source` shall apply the four rules in order, shall read an existing file
with no `.csv` suffix, and shall report a mistyped `.csv` path as a missing file
rather than as an invalid repository name.

**L3-SRC-004** · Parent: L2-SRC-002 · Verification: T
`resolve_sources` shall return references in the order the arguments were
written whatever their kind, shall produce the same result for the same
arguments on every run, and shall count references read, accepted and rejected
across every kind of source.

**L3-SRC-005** · Parent: L2-SRC-003 · Verification: T
A repository named by two sources shall appear once, at the position of its
first mention, and the repetition shall be reported as `GM-ING-015` naming the
earlier source. Comparison shall ignore case.

## L3-VAL: Name validation

**L3-VAL-001** · Parent: L2-VAL-001 · Verification: T
`validate_owner` shall accept a name of 1 to 39 characters drawn from letters,
digits and hyphens, with no leading hyphen, no trailing hyphen and no
consecutive hyphens, and shall reject anything else.

**L3-VAL-002** · Parent: L2-VAL-002 · Verification: T
`validate_repoid` shall accept a name of 1 to 100 characters drawn from letters,
digits, hyphens, underscores and dots, excluding `.`, `..` and any name ending
in `.git`.

**L3-VAL-003** · Parent: L2-VAL-003 · Verification: T
Both validators shall return `None` for an accepted name and a phrase naming the
first problem for a rejected one.

**L3-VAL-004** · Parent: L2-VAL-002 · Verification: T
The `.git` rejection shall match the suffix case-insensitively and shall not
reject a name that merely contains `git` or `.git` elsewhere.

## L3-ERR: Error reporting and taxonomy

**L3-ERR-001** · Parent: L2-ERR-001 · Verification: T
A missing path shall raise `SourceNotFoundError`, an unopenable path
`SourceUnreadableError`, a file with no header `SourceEmptyError`, a header
lacking or duplicating a required column `HeaderError`, non-UTF-8 bytes
`SourceDecodeError`, and content that is binary or unparseable
`MalformedCsvError` — each rendering its code.

**L3-ERR-002** · Parent: L2-ERR-002 · Verification: T
A rejected row shall append a `RowIssue` carrying its code, physical line and a
message naming the offending value, rendered as `path:line: [CODE] message`.

**L3-ERR-003** · Parent: L2-ERR-003 · Verification: T
With `strict=True` the first `RowIssue` shall instead raise `StrictModeError`
naming that issue, and a file with no issues shall produce the same result under
both modes.

**L3-ERR-004** · Parent: L2-ERR-004 · Verification: T
Every ingestion error shall derive from `IngestError`, and the codes of the
error classes shall be pairwise distinct.

## L3-CON: Concurrency

**L3-CON-001** · Parent: L2-CON-001 · Verification: T
`read_repository_csvs` shall read its sources on a `ThreadPoolExecutor`, shall
return one result per source, shall start no worker for an empty input, and
shall propagate strict-mode failures out of the pool.

**L3-CON-002** · Parent: L2-CON-002 · Verification: T
Results shall be ordered by input position, repeated runs over the same sources
shall be identical, and when two sources fail the error raised shall be the one
belonging to the earlier source.

**L3-CON-003** · Parent: L2-CON-003 · Verification: T
Reads performed with 1, 2 and 16 workers shall produce identical results, and a
worker count exceeding the source count shall be harmless.

## L3-CLI: CLI capability surface

**L3-CLI-001** · Parent: L2-CLI-001 · Verification: T
`github-metrics validate` shall accept one or more paths, shall require at least
one, shall appear in the command list, and shall summarise a multi-file run with
a combined total.

**L3-CLI-002** · Parent: L2-CLI-002 · Verification: T
`validate` shall succeed with no `GITHUB_TOKEN` in the environment, in the same
conditions under which `rate-limit` refuses to run.

**L3-CLI-003** · Parent: L2-CLI-003 · Verification: T
`--format json` shall write parseable JSON to standard output, and `--output`
shall write the report to the named file instead.

**L3-CLI-004** · Parent: L2-CLI-004 · Verification: T
`validate` shall exit 0 for a clean read, 3 when rows were rejected, and 2 when a
source could not be read or a strict-mode read was abandoned.

**L3-CLI-005** · Parent: L2-CLI-005 · Verification: T
`github-metrics closed-issues OWNER/REPOID` shall report the closed and open
counts, the tracker state and the weight; `--explain` shall append the band
table; `--format json` shall emit the same values as parseable JSON; a
malformed slug shall be a usage error; and an unreadable repository shall exit
4 carrying `GM-COL-001`.

## L3-LOG: Diagnostic logging

**L3-LOG-001** · Parent: L2-LOG-001 · Verification: T
Each `RowIssue` shall be logged at DEBUG on the `github_metrics.sources.csv_inventory` logger,
and each completed file shall be logged at INFO with its accepted, read and
rejected counts.

**L3-LOG-002** · Parent: L2-LOG-002 · Verification: T
Collecting an unremarkable repository shall emit no record at INFO or above on
the `github_metrics` logger, while the same call at DEBUG shall still report
what was collected.

## L3-COL: Collection over an inventory

**L3-COL-001** · Parent: L2-COL-001 · Verification: T
`collect_all` shall return one outcome per reference, carrying either the
metadata or the error, shall continue past a repository that cannot be read,
shall accept an empty list without contacting the API, and shall name the
failures in the log.

**L3-COL-002** · Parent: L2-COL-002 · Verification: T
`collect_all` shall return results in input order regardless of completion
order, shall never exceed the requested worker count nor the number of
references, and shall produce the same ordering for the same inventory on every
run.

**L3-COL-003** · Parent: L2-COL-003 · Verification: T
`check_budget` shall require exactly one point per repository with no reserve,
shall report the requirement and the shortfall, and shall raise
`RateLimitExhaustedError` (`GM-COL-004`) before any collection when the
remaining points cannot cover the run.

## L3-ROW: Row assembly

**L3-ROW-001** · Parent: L2-ROW-001 · Verification: T
`build_row` shall reproduce the reference row from `METRICS.md`, shall score
the distinct version count rather than releases plus tags, shall stamp every
row with the run's `scan_id` and `scan_date`, shall emit every score as a
float, and shall set `total_score` to the sum of the six components.

**L3-ROW-002** · Parent: L2-ROW-001 · Verification: T
`is_trusted_org` and `trusted_org_bonus` shall resolve through the same
registry so they cannot disagree, `owner` shall be the value the input gave,
and `name`, `url` and `organization` shall be the values GitHub reported.

**L3-ROW-003** · Parent: L2-ROW-002 · Verification: T
`build_empty_row` shall fill `name`, `owner`, `url`, `scan_date` and
`scan_id` from the input and the scan, and shall leave every other column
empty rather than zero, `organization` included.

## L3-OUT: Result output and destinations

**L3-OUT-001** · Parent: L2-OUT-001 · Verification: T
`SoftwareRow.to_header()` shall derive the twenty column names and their
order from the dataclass field order, matching the header documented in
`METRICS.md`, and the documented reference row shall render exactly.

**L3-OUT-002** · Parent: L2-OUT-002 · Verification: T
`write_csv` shall emit the header for an empty sequence, preserve the given row
order, and terminate lines with LF on every platform.

**L3-OUT-003** · Parent: L2-OUT-003 · Verification: T
`write_json` shall emit an array of objects whose keys are the selected column
names, keep integers, floats and booleans as JSON types, render `datetime` and
`UUID` as the same strings the CSV uses, and repeat the run identity per
object.

**L3-OUT-004** · Parent: L2-OUT-007 · Verification: T
A row with no measurements shall keep its identity columns and render every
metric and score as an empty CSV field and as JSON `null`, while a row measured
as zero shall render `0`.

**L3-OUT-005** · Parent: L2-OUT-007 · Verification: T
Booleans shall render as `true` and `false`, and floats shall render at full
repr precision.

**L3-OUT-006** · Parent: L2-OUT-005 · Verification: T
`resolve_fields` shall return every column for `None`, an empty selection or a
selection of blanks; shall return canonical order regardless of the order
given; and shall accept mixed case, padding and duplicates.

**L3-OUT-007** · Parent: L2-OUT-006 · Verification: T
`resolve_fields` shall raise `UnknownFieldError` carrying `GM-OUT-001` for an
unrecognised name, naming the closest valid match when one exists.

**L3-OUT-008** · Parent: L2-OUT-004 · Verification: T
`render_console` shall emit one aligned label-and-value line per selected
column, separate consecutive repositories with a rule, mark an uncollected
value rather than leaving the line blank, and state plainly when there are no
rows.

**L3-OUT-009** · Parent: L2-OUT-008 · Verification: T
`resolve_destination` shall return `None` for no destination, append
`githubmetrics.csv` or `githubmetrics.json` inside a directory or a
separator-terminated path, use a named file as given, and raise
`OutputDestinationError` carrying `GM-OUT-002` when the parent directory is
absent.

**L3-OUT-010** · Parent: L2-OUT-009 · Verification: T
`ScanIdentifier` shall default to a fresh UUID4 and a timezone-aware UTC
timestamp, shall reject a naive timestamp, and one instance shall stamp every
row of a run.

**L3-OUT-011** · Parent: L2-OUT-010 · Verification: T
`document_path` shall nest by owner, shall fold both segments to lower case so
that two spellings of one repository produce one path, and shall keep
`foo-bar/baz` and `foo/bar-baz` distinct; `prepare_root` shall default to
`githubmetrics`, create a missing directory, and raise `DocumentDirectoryError`
carrying `GM-OUT-003` for a path that is not a directory; and a document shall
be written with LF endings on every platform.

**L3-OUT-012** · Parent: L2-OUT-011 · Verification: T
`build_document` shall emit every `SoftwareRow` column in canonical order
followed by exactly one `contributors` key, shall keep JSON-native types, shall
render an uncollected value as `null`, shall stamp every contributor with the
run identity, and shall ignore any field selection applied to the tabular
artifact.

**L3-CLI-008** · Parent: L2-CLI-007 · Verification: T
`github-metrics scan` shall accept the same sources as `validate`, write one
row per accepted reference in input order, resolve a directory to
`githubmetrics.csv`, render to the console when no destination is given, emit
JSON to either, select columns in canonical order, and stamp every row of one
run with the same scan.

**L3-CLI-009** · Parent: L2-CLI-007 · Verification: T
`github-metrics scan` shall exit 4 when a repository could not be collected
and 3 when only an input reference was rejected, shall name each failed
repository on standard error, shall still write a well-formed file in both
cases, and shall reject an unwritable destination or an unaffordable budget
before collecting anything.

**L3-CLI-010** · Parent: L2-CLI-007 · Verification: T
`github-metrics scan` shall write both artifacts into one directory, defaulting
to `githubmetrics`, shall take no flag governing which of the two is produced,
shall stamp both with one `scan_id` and one `scan_date`, and shall report how
many documents it wrote.

## L3-MET: Metric collection

**L3-MET-001** · Parent: L2-MET-001 · Verification: T
`get_closed_issues` shall query the `issues` connection only, never
`pullRequests`, and shall return the closed and open totals with pull requests
excluded.

**L3-MET-002** · Parent: L2-MET-002 · Verification: T
The query shall request `totalCount` and no `nodes`, shall issue exactly one
request per repository, and shall report a genuinely empty repository as zero
rather than as one.

**L3-MET-003** · Parent: L2-MET-003 · Verification: T
A GraphQL failure shall raise `RepositoryNotFoundError` (`GM-COL-001`) when any
error is typed `NOT_FOUND` and `GraphQLQueryError` (`GM-COL-002`) otherwise,
whether the transport raises it or returns it in the payload, including when a
`NOT_FOUND` arrives among several errors that the transport collapses into a
generic failure, and including a response carrying no `data` object or a null
repository with no error.

**L3-MET-004** · Parent: L2-MET-004 · Verification: T
`ClosedIssueCounts` shall carry `issues_enabled`, a disabled tracker shall be
logged at WARNING, an enabled but empty tracker at INFO, and every collection
shall log its counts with the pull-request exclusion stated.

**L3-MET-005** · Parent: L2-MET-005 · Verification: T
`get_release_counts` shall request `releases { totalCount }` and
`refs(refPrefix: "refs/tags/") { totalCount }` in one query with no `nodes`,
return both separately, expose `tags_without_releases` clamped at zero, and
raise `RepositoryNotFoundError` for a null repository.

**L3-MET-006** · Parent: L2-MET-006 · Verification: T
`ReleaseCounts.distinct_versions` shall equal the tag count whenever releases
do not exceed tags, shall equal the release count when they do, shall never
exceed `legacy_sum`, and `legacy_sum` shall exceed `distinct_versions` by
exactly the release count.

**L3-MET-007** · Parent: L2-MET-007 · Verification: T
Collection shall log both counts and the distinct total at INFO, the tags
carrying no release at DEBUG, a tags-only project and a project that has
shipped nothing at INFO, a release count exceeding the tag count at WARNING as
irreproducible, and the previous definition's value with its inflation factor
at DEBUG.

**L3-CLI-006** · Parent: L2-CLI-005 · Verification: T
`github-metrics releases OWNER/REPOID` shall report both counts and the
distinct total, flag a tags-only project, emit the same values under
`--format json`, exit 4 carrying `GM-COL-001` for an unreadable repository,
and reject a malformed slug as a usage error.

**L3-CLI-007** · Parent: L2-CLI-006 · Verification: T
`github-metrics bands` shall print all five tables, `bands METRIC` shall print
one, every table shall carry its boundaries, an unrecognised metric shall be a
usage error listing the valid names, and the command shall need no token.

**L3-MET-008** · Parent: L2-MET-008 · Verification: T
`age_days` shall measure from `created_at` to `scan_date`, be identical for
repeated calls with the same arguments, keep full float precision, and differ
from the reference row's value by the 129 seconds that row was measured after
its own `scan_date`.

**L3-MET-009** · Parent: L2-MET-008 · Verification: T
`last_update_hours` shall measure from `updated_at` to `scan_date`, report zero
for a repository updated at the scan instant, and compose with the timestamps
collection.

**L3-MET-010** · Parent: L2-MET-009 · Verification: T
A timestamp later than `scan_date` shall be logged at WARNING with the size of
the discrepancy and clamped to zero, and a naive timestamp on either side shall
raise `ValueError` naming which value was at fault.

**L3-MET-011** · Parent: L2-MET-008 · Verification: T
`get_timestamps` shall fetch `createdAt`, `updatedAt` and `pushedAt` in one
query, return timezone-aware values, tolerate a repository never pushed to,
raise `GraphQLQueryError` for an unparseable timestamp and
`RepositoryNotFoundError` for a null repository.

**L3-MET-012** · Parent: L2-MET-010 · Verification: T
`get_repository` shall return stars, forks, all three timestamps, both issue
counts, the tracker setting, releases and tags from a single query carrying no
`nodes` selection, shall derive `distinct_versions` exactly as
`collect.releases` does, and shall raise `RepositoryNotFoundError` for a null
repository and `GraphQLQueryError` for an unparseable timestamp.

**L3-MET-013** · Parent: L2-MET-011 · Verification: T
`organization` shall be the owner's login when `owner.__typename` is exactly
`Organization` and empty otherwise, including for an unrecognised type, and a
personally owned repository and a disabled issue tracker shall each be reported
in the log.

**L3-MET-014** · Parent: L2-MET-011 · Verification: T
A repository GitHub reports under a different owner shall set
`was_transferred` and shall raise `RepositoryMovedError` (`GM-COL-003`) naming
the current location; a difference of case alone shall not count as a transfer,
because GitHub account names are case-insensitive.

**L3-MET-015** · Parent: L2-MET-011 · Verification: T
`resolved_name` shall carry the name GitHub reports, obtained from the same
query at no additional cost, and shall fall back to the supplied `repoid` when
the API gives none.

**L3-MET-016** · Parent: L2-MET-011 · Verification: T
A repository GitHub reports under a different name shall set `was_renamed` and
shall raise `RepositoryMovedError` (`GM-COL-003`); the warning shall name the
current `owner/name` and state that no data was collected, so the inventory can
be corrected by copying it.

**L3-MET-017** · Parent: L2-MET-012 · Verification: T
`get_contributors` shall read the ranked list from REST and every account's
detail from one aliased GraphQL document containing no `nodes`, shall alias by
position rather than by login, shall record an account GitHub answers with
`null` using its login and its commits, shall leave `foreign` and `adversarial`
unset, shall log the truncation when the list reaches the limit, and shall
raise `ContributorCollectionError` (`GM-COL-005`) when the list cannot be read.

**L3-MET-018** · Parent: L2-MET-013 · Verification: T
`Geocoder.locate` shall return an empty address for a blank location without
contacting the service, an address carrying only `query` for a location that
resolved to nothing or whose lookup failed, and a decomposed address otherwise
with `""` for each component the match lacks; coordinates shall be `None`
rather than `0.0` when unresolved; a repeated location shall be requested once;
and the returned address shall be immutable.

## L3-SCR: Scoring

**L3-SCR-001** · Parent: L2-SCR-001 · Verification: T
`score_closed_issues` shall implement the published bands, mapping every count
from 0 upward to exactly one weight in 0.1-1.0, with 500 scoring 1.0 rather
than falling through, monotonically non-decreasing, and with the table ordered
and free of duplicate bounds.

**L3-SCR-002** · Parent: L2-SCR-002 · Verification: T
A negative count shall be logged at WARNING and scored as zero, and the chosen
band shall be logged at DEBUG.

**L3-SCR-003** · Parent: L2-SCR-001 · Verification: T
`score_releases` shall implement the published bands, mapping every count from
0 upward to exactly one weight in 0.0-1.0, scoring 0 as 0.0 rather than the
floor closed issues uses, never producing 0.9, saturating at 80, and
monotonically non-decreasing.

**L3-SCR-004** · Parent: L2-SCR-002 · Verification: T
A negative version count shall be logged at WARNING and scored as zero, and the
chosen band shall be logged at DEBUG.

**L3-SCR-005** · Parent: L2-SCR-003 · Verification: T
`score_prevalence` shall return `20 x max(issue weight, release weight)`, be
non-decreasing in both inputs across their ranges, stay within 0.0 to 20.0, and
score a repository with one closed issue no lower than the same repository with
none.

**L3-SCR-006** · Parent: L2-SCR-004 · Verification: T
The issue weight shall be excluded and the release weight used alone whenever
there is no issue evidence - the tracker disabled, or no closed issues -
reported at INFO in both cases, so that a repository with no closed issues and
no versions scores 0.0 while one closed issue or one version scores 2.0.

**L3-SCR-007** · Parent: L2-SCR-003 · Verification: T
The component shall reach its 20.0 maximum for every repository measured, shall
still order projects below the ceilings, and shall log saturation, the absence
of any evidence, and which signal was the stronger.
**L3-SCR-008** · Parent: L2-SCR-001 · Verification: T
`last_update_weight` shall reproduce the weight of the implementation it
replaces for every whole hour from 0 to five years, score each documented
boundary inclusively, never rise as the hours rise, and map every input to one
of the six documented weights.

**L3-SCR-009** · Parent: L2-SCR-005 · Verification: T
The dropped `0.05 year` boundary shall be shown to have carried the same weight
on both sides, no remaining boundary shall separate equal weights, and the
bounds shall be the exact integers 876, 2190, 4380, 8760 and 26280.

**L3-SCR-010** · Parent: L2-SCR-002 · Verification: T
A negative number of hours shall be logged at WARNING as clock skew and scored
as zero hours, where the implementation it replaces accepted it silently.

**L3-SCR-011** · Parent: L2-SCR-006 · Verification: T
`score_last_update` shall return `LAST_UPDATE_POINTS` of 15.0 multiplied by the
weight, reproduce the reference row's 15.0 from 8.10177526 hours, score a
repository untouched for four years as 0.0, and log the score against its
budget.

**L3-SCR-012** · Parent: L2-SCR-007 · Verification: T
`maturity_weight` shall compare every threshold against the age in years, so
that the "too young" band covers ages below three months rather than below six
hours, and the inputs whose weight changes as a result shall be exactly days 1
through 91.

**L3-SCR-013** · Parent: L2-SCR-001 · Verification: T
`maturity_weight` shall implement the published bands, score each boundary as
documented, never decrease as a repository ages, map every age to one of seven
weights, place its last boundary at four years, and leave no boundary
separating equal weights.

**L3-SCR-014** · Parent: L2-SCR-002 · Verification: T
A negative age shall be logged at WARNING and scored as zero days, where the
implementation it replaces returned zero silently.

**L3-SCR-015** · Parent: L2-SCR-006 · Verification: T
`score_maturity` shall return `MATURITY_POINTS` of 15.0 multiplied by the
weight, and reproduce the reference row's 12.0 from an age of
736.5466017006597 days.

**L3-SCR-016** · Parent: L2-SCR-008 · Verification: T
The fork implementation being replaced shall be shown to return `None` for
every input and to raise when multiplied by its budget; `forks_weight` shall be
non-decreasing across its range, score 109 as 0.8 and 110 as 0.9, and reach its
maximum at 150.

**L3-SCR-017** · Parent: L2-SCR-005 · Verification: T
The star and fork tables shall carry identical bands below 90, agree on every
weight for counts below 90, place the fork ceiling below the star ceiling, and
share their threshold vocabulary except for the fork-only bound of 110.

**L3-SCR-018** · Parent: L2-SCR-001 · Verification: T
`stars_weight` and `forks_weight` shall score every documented boundary as
published and map their counts onto all eleven weights from 0.0 to 1.0.

**L3-SCR-019** · Parent: L2-SCR-002 · Verification: T
A negative star or fork count shall be logged at WARNING and scored as zero.

**L3-SCR-021** · Parent: L2-SCR-009 · Verification: T
`MAX_TOTAL_SCORE` shall equal 85.0 and shall be computed from the component
weights, which shall sum to 75.0 without the trusted-organisation bonus.
`score_total` shall return a float, shall reproduce the reference row's 72.0,
shall return 0.0 for a repository with nothing, and shall report rather than
clamp a total above the maximum, naming the component that exceeded its share.

**L3-SCR-020** · Parent: L2-SCR-006 · Verification: T
`score_stars` and `score_forks` shall return budgets of 10.0 and 15.0
multiplied by their weights, and reproduce the reference row's 10.0 from 64,574
stars and 15.0 from 6,900 forks.

## L3-TRU: Trust policy

**L3-TRU-001** · Parent: L2-TRU-001 · Verification: T
`is_trusted_org` shall return True for `spring-projects`, `google` and
`hibernate`, and False for any other owner, with the default list holding
exactly those three.

**L3-TRU-002** · Parent: L2-TRU-001 · Verification: T
Matching shall ignore case and surrounding whitespace on both the queried owner
and the registry's own keys, and each check shall be logged at DEBUG.

**L3-TRU-003** · Parent: L2-TRU-002 · Verification: T
`institution_for` shall return the recorded institution for a trusted owner and
`None` otherwise, with the names written as the institutions write them -
`VMware`, `Google`, `Red Hat` - and no value ending in punctuation.

**L3-TRU-004** · Parent: L2-TRU-003 · Verification: T
A caller-supplied mapping shall replace the default entirely, an empty mapping
shall trust nobody, neither the default nor a registry's entries shall be
mutable, and the loaded list shall be logged at DEBUG.
**L3-TRU-005** · Parent: L2-TRU-004 · Verification: T
`score_org_bonus` shall award `ORG_BONUS_POINTS` of 10.0 to an owner on
the list and 0.0 to any other, with no value in between, following the same
case rules as the membership check, honouring a caller-supplied registry, and
agreeing with `is_trusted_org` for every owner.

**L3-TRU-006** · Parent: L2-TRU-004 · Verification: T
An awarded bonus shall be logged at INFO naming the institution behind the
owner, and a refused one at DEBUG naming the owner.

## L3-CFG: Credentials

**L3-CFG-001** · Parent: L2-CFG-001 · Verification: T
`Settings.from_env` shall prefer an explicit token over `GITHUB_TOKEN`, strip
it, fall back to the environment when the explicit value is blank or absent,
raise `MissingCredentialsError` (`GM-CFG-001`) when neither supplies one, and
log which route supplied it without logging the value.

**L3-CFG-002** · Parent: L2-CFG-004 · Verification: T
`describe_token_kind` shall name every documented token prefix and report an
unrecognised prefix as such.

**L3-CFG-003** · Parent: L2-CFG-002 · Verification: T
`verify_credentials` shall read the scopes and the REST and GraphQL budgets
from the rate-limit response, and shall treat a fine-grained token's empty
scope list as expected rather than as a fault.

**L3-CFG-004** · Parent: L2-CFG-003 · Verification: T
A rejected token shall raise `InvalidCredentialsError` (`GM-CFG-002`), any other
API failure shall raise rather than read as success, and a client passed in by
the caller shall not be closed by the check.

**L3-CFG-005** · Parent: L2-CFG-004 · Verification: T
No log record shall contain the token in whole or in part, while the kind,
length, scopes and both budgets shall appear, and an empty scope list shall be
explained.

**L3-CFG-006** · Parent: L2-CFG-003 · Verification: T
The CLI shall exit 7 carrying `GM-CFG-001` when no token is available, naming
both `--token` and `GITHUB_TOKEN` in the message, and exit 8 carrying
`GM-CFG-002` when GitHub rejects one.

**L3-CFG-007** · Parent: L2-CFG-002 · Verification: T
`--no-verify-token` shall skip the check, and a command needing no credentials
shall never reach it.

**L3-CFG-008** · Parent: L2-CFG-005 · Verification: T
`--token-file` shall read a token from a file with surrounding whitespace
stripped, shall reject an empty or unreadable file and the combination of
`--token` and `--token-file` as usage errors, and shall not echo the token.
